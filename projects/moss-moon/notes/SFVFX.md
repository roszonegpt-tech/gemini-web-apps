# Sprite Fusion pixel-art VFX — integration brief (for the FX agent)

**What it is.** 25 open-source (MIT, © 2026 Hugo Duprez) pixel-art effects from https://www.spritefusion.com/pixel-art-vfx, one dependency-free TypeScript file each. They are *vendored unmodified* in `art/vendor/spritefusion-vfx/*.ts` and converted by `node tools/port-sfvfx.js` into one classic script **`src/systems/sfvfx.js`** exposing `MM.sfvfx.<name>(options) → {update(dt), draw(frame, layer?), done()}`.
Verified (Node 22 + Playwright): `node tests/sfvfx-test.js` — all 25 construct, step, render pixels (contact sheet `tests/out/sfvfx-sheet.png`). Credit them in the Credits screen (SCREENS agent) and in README.

**Effects (camelCase keys):** combat `explosion impact slash muzzleFlash blood movement(dash/blink)`; elements `fire lightning ice poison`; magic `energy shield blackHole holyLight`; feedback `heal powerUp pickup sparkle`; environment `rain snow fog embers fireflies fallingLeaves bubbles`.
Looping ambient ones (`rain snow fog embers fireflies fallingLeaves bubbles blackHole blood`) never report done() until told to stop (read each file's `stop`/`duration` option or method — check the source of each before use).

## How they draw
`Frame = {w,h,ox,oy,color:Uint32Array,light:Uint32Array}` in **logical pixels**, little-endian RGBA packed in Uint32 (`a<<24|b<<16|g<<8|r`). Effects write a *color* buffer (opaque pixel art, already dithered/banded — pixel-art look) and a *light* buffer (glow contribution). Coordinates passed in options (x, y, ground, area, box) are in **units where 1 logical pixel = PX = 2 units**; sizes scale with `size` (S=1 ≈ 18-logical-px blast radius for explosion — a good "medium spell" on our 512×320 canvas, where the witch is ~36px tall).
Many take `ground` (y or function of x) and `surface` color, `seed`, `palette/ramp/colors`, `shake(trauma)` and `ripple(x,y,r0,r1,dur,amp,w)` callbacks (hook those to `MM.camera.shake` and your distortion blit).

## What the bridge (`src/systems/vfx-bridge.js`, owner FX) must do
1. **One shared Frame** sized to the 512×320 scene (logical pixels = game pixels, i.e. unit = 2×game px): clear once per frame, let every active effect draw into it (`draw(frame,'back')` before entities via the `drawGround`/`drawables` hook area, `draw(frame,'front')` after entities via `postEffects`), then `putImageData` the color buffer into an offscreen canvas and `drawImage` it with the camera offset (integer); blit the `light` buffer with `globalCompositeOperation='lighter'` at low alpha (scaled by quality) — or feed it to `MM.lighting` — so glow fits the soft filter. Only allocate the Frame/offscreen once; only run when any effect is active; skip entirely if `fxIntensity`/quality is off.
2. **World→frame mapping:** use `worldToCanvas(x,y)` (baseline) minus shake offset → game px → units ×2; effects with a `ground` argument get the target's foot y (iso 3/4 view: side-view floor rings become flat ellipses at the foot — fine and already how the effects are drawn; use `size` to fit tiles).
3. **API:** `MM.vfx.play(name, worldX, worldY, opts) → handle`, `MM.vfx.attach(name, actor, opts)` for persistent ones (fire on burning enemy, shield on player, fog/rain/snow zones), `MM.vfx.stop(handle)`, `MM.vfx.clear()`, `MM.vfx.stats()`; per-class caps (e.g. ≤6 simultaneous bursts, ≤2 ambient fields), pooling of options objects, off-screen culling (don't update effects whose area is far off-screen unless one-shot in progress), lifetime cleanup, cleared on state changes (`sim:'none'` states) and region changes, `settings.reducedMotion`/`reducedFlashes` (drop lightning/holyLight/explosion flash intensity: pass lower size or skip light layer; cap flashes ≤3/s) and `particles`/`fxIntensity` scaling (size/density option).
4. **Palette harmony:** every effect has color options (ramps/palettes); pass Moss & Moon palette ramps (moon lavender/silver-blue, ember gold/orange, thorn green, frost cyan, star cream/gold) so effects feel native — don't ship default neon colors where an option exists. Keep effects readable: never cover enemies/telegraphs/prompts (draw 'back' layer under entities where it exists).
5. **Gameplay mapping (anticipation → action → impact → aftermath):**
   - Moonbolt: charge `sparkle`(small, lavender) → projectile trail `energy`/`movement`-style streak (custom) → impact `impact`+`sparkle` → faint `fog` residue. Ember Bloom: `fire` charge → `explosion`(size .6, fire-heavy, `earth` low) → `embers` aftermath + burning `fire` attach on targets. Thornbind: `poison` (recolor green) roots zone + `fallingLeaves` burst, snare boundary ring. Frostbell: `ice` crystals ring + `snow` puff, shatter combo = `ice`+`impact`. Starfall: telegraph (own ring) → `holyLight` column + `explosion`(size 1) + `sparkle`; final boss: `blackHole` for Hollow Moon phase 2.
   - Hits: `impact` (scaled by damage), crits: `impact`+`slash`; kills: `explosion`(size .35)/`sparkle`; player hurt: `blood`→ recolored to a soft red spark or skipped (family-friendly option: use `impact` only; setting `gore` off by default).
   - Farming: plant → soil `movement`-dust/`explosion` tiny dirt (earth only, size .2); water → `bubbles`/`rain` mini splash; harvest → `pickup`+`sparkle`; level-up → `powerUp`; heal/mana potions → `heal` (kind heal/mana); shields → `shield` attached; pickups → `pickup`; broom takeoff/landing → `movement` dust; mount/dash → `movement`.
   - Ambient/weather: `rain` (with splashes), `snow` (Frostpeak), `fog` (swamp/forest, restoration lifts it), `embers` (hearth/Old Crypt), `fireflies` (grove night — density rises with restoration level), `fallingLeaves` (forest/grove), `bubbles` (swamp pools). Respect `MM.settings.particleScale()`.
   - Region restoration: `holyLight` column at the Moonwell + expanding ring (own) + `sparkle`/`fireflies` bloom wave; `powerUp` at player; camera impulse; `fog` fade-out.
   - Doors/interiors: tiny `sparkle` on enter; interior hearth `fire` (attached, small), candles `fireflies`-like motes.
6. **Tests:** extend `tests/fx-*.js`: bridge renders each mapped effect to the scene (screenshots 2× reviewed visually), cap/no-growth over 3000 frames, ms/frame per quality, reduced-flash assertions, nothing runs while `MM.screens.current.sim==='none'`.
7. Keep `src/systems/sfvfx.js` generated — never hand-edit; re-run `node tools/port-sfvfx.js` after changing the vendored sources (they should stay unmodified; do adaptation in the bridge via options).
